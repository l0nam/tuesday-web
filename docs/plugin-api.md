# API плагина Tuesday

Плагин Minecraft-сервера отправляет события на сайт по HTTPS. Сайт начисляет Вторнички по правилам из `lib/rewards/config.ts`. Плагину достаточно сообщать, что произошло.

API решает две задачи:

1. **Передача событий.** Плагин сообщает о достижениях, кланах, наигранном времени и активности игрока. Эти же запросы обновляют публичный профиль: онлайн, клан и донат-статус.
2. **Выдача покупок.** Плагин получает заказы магазина с сайта и выполняет команды консоли Minecraft.

## 1. Настрой подключение

Перед запуском плагина проверь три вещи:

- Сайт доступен по HTTPS.
- В конфигурации плагина указан тот же секрет, что и в переменной `PLUGIN_API_SECRET` на сайте.
- Часы сервера Minecraft синхронизированы с актуальным временем.

Для тестирования запросов используй готовые примеры:

- [`examples/send-event.sh`](examples/send-event.sh) для Bash, `curl` и `openssl`.
- [`examples/TuesdayApi.java`](examples/TuesdayApi.java) для Java 17 или новее. Дополнительные библиотеки не нужны.

## 2. Подписывай каждый запрос

API проверяет подпись HMAC-SHA256. Она подтверждает, что запрос сформирован с использованием общего секрета.

Передавай два заголовка:

| Заголовок             | Значение                                        |
| --------------------- | ----------------------------------------------- |
| `X-Tuesday-Timestamp` | Время отправки в миллисекундах Unix epoch       |
| `X-Tuesday-Signature` | HMAC-SHA256-подпись в шестнадцатеричном формате |

Подпись вычисляется по формуле:

```text
hex(HMAC-SHA256(secret, timestamp + "\n" + METHOD + "\n" + path + "\n" + body))
```

При формировании подписи соблюдай следующие правила:

- `METHOD` указывай в верхнем регистре: `GET`, `POST`.
- `path` указывай без домена и query-параметров. Например, `/api/plugin/events`.
- `body` должен точно совпадать с отправляемым телом запроса в UTF-8. Для `GET` без тела используй пустую строку.
- Query-параметры передавай в URL, но не включай в подписываемый путь.
- Не добавляй лишние пробелы или переводы строк в тело. Даже одно отличие изменит подпись.

Сайт отклоняет запросы, если время в подписи отличается от текущего более чем на 5 минут. Если перед сайтом стоит прокси, который изменяет путь запроса, подпись также перестанет совпадать.

## 3. Обрабатывай ошибки API

При ошибке сайт возвращает JSON следующей структуры:

```json
{
  "error": {
    "code": "...",
    "message": "..."
  }
}
```

Используй HTTP-статус и поле `code`, чтобы определить дальнейшие действия.

| HTTP  | `code`                          | Что делать                                                   |
| ----- | ------------------------------- | ------------------------------------------------------------ |
| `401` | `unauthorized`, `bad_signature` | Проверь заголовки и HMAC-подпись                             |
| `401` | `stale_timestamp`               | Проверь время на сервере Minecraft                           |
| `400` | `bad_json`, `bad_request`       | Исправь JSON или поля запроса                                |
| `404` | `not_found`                     | Проверь ID заказа                                            |
| `409` | `conflict`                      | Заказ уже закрыт с другим результатом                        |
| `413` | `too_large`                     | Уменьши тело запроса до допустимого размера, максимум 256 КБ |

Ошибки сети и ответы `5xx` обычно можно повторить. Ошибки `400` и `401` сначала нужно исправить. Для заказов учитывай результат операции, чтобы повторная попытка не привела к повторной выдаче товара.

## 4. Отправляй события

**Метод:** `POST /api/plugin/events`

Одним запросом можно передать от 1 до 50 событий.

Пример события достижения:

```json
{
  "events": [
    {
      "type": "achievement",
      "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
      "name": "Steve",
      "achievementId": "story/mine_diamond",
      "difficulty": "normal"
    }
  ]
}
```

`uuid` можно отправлять с дефисами или без них. Поле `name` необязательно, но лучше передавать ник игрока: сайт использует его для отображения профиля.

Каждое событие должно содержать `type` и `uuid`. Остальные поля зависят от типа события.

### Типы событий

| `type`            | Дополнительные поля                          | Что делает сайт                                                                                              |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `achievement`     | `achievementId`, `difficulty`                | Начисляет награду по сложности. За одно достижение игрок получает её один раз                                |
| `clan`            | `clanId`, `members`                          | При количестве жителей от 10 начисляет разовый бонус игроку. Бонус доступен один раз для всех кланов вместе |
| `playtime`        | `totalSeconds`                               | Начисляет награду за каждый полный час нового игрового времени                                               |
| `activity`        | `activity`, `eventId`, `amount` для `custom` | Начисляет награду по коду активности. Один `eventId` оплачивается игроку один раз                            |
| `presence`        | `online` (`true` или `false`)                | Обновляет онлайн игрока, день последнего входа и серию заходов                                               |
| `clan_membership` | `clan` с данными клана или `null`           | Обновляет информацию о клане в публичном профиле                                                            |
| `donate`          | `tier`, необязательное `expiresAt`           | Обновляет донат-статус в публичном профиле                                                                   |

События `presence`, `clan_membership` и `donate` не начисляют награды. Они нужны для публичного профиля игрока.

### Идентификаторы

Поля `achievementId`, `clanId` и `eventId` должны содержать строки длиной до 100 символов. Допустимы буквы, цифры и символы:

```text
. _ : -
```

### Награды за активность

По умолчанию сайт поддерживает следующие коды:

| Код       | Активность                  |
| --------- | --------------------------- |
| `event`   | Ивент                       |
| `contest` | Конкурс                     |
| `quest`   | Квест                       |
| `vote`    | Голосование                 |
| `custom`  | Пользовательская активность |

Для `custom` передавай дополнительное поле `amount`. Его максимальное значение задаётся через `customActivityMax`.

Список активностей, размеры наград и остальные правила находятся в `lib/rewards/config.ts`.

### Достижения

Для Bukkit получай достижения через `PlayerAdvancementDoneEvent`. Сложность определяй по конфигурации плагина, например через таблицу «ключ достижения → сложность».

Не отправляй служебные достижения рецептов. Их ключи начинаются с `minecraft:recipes/`.

## 5. Обновляй публичный профиль

Профиль доступен по адресу `/players/{ник}`. Сайт создаёт его для любого игрока, о котором получил хотя бы одно событие, даже если игрок не регистрировался на сайте.

### `presence`: онлайн и серия заходов

Пример:

```json
{
  "type": "presence",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "name": "Steve",
  "online": true
}
```

Настрой отправку так:

1. При входе игрока отправляй `online: true`.
2. Каждые 5 минут, пока игрок находится на сервере, отправляй повторный сигнал `online: true`.
3. При выходе отправляй `online: false`.

Сайт считает игрока онлайн, если последний сигнал получен не более 10 минут назад. Если сервер аварийно завершит работу и события выхода не отправятся, отметка «Онлайн» всё равно погаснет автоматически.

Каждый сигнал `online: true` отмечает текущий день как день активности. На этих данных строятся серия последовательных дней с заходами и календарь активности.

Дни рассчитываются по часовому поясу сайта: `SITE_TIMEZONE`. По умолчанию это `Europe/Moscow`.

### `playtime`: общее время и статистика по дням

Пример:

```json
{
  "type": "playtime",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "name": "Steve",
  "totalSeconds": 86400
}
```

Поле `totalSeconds` содержит **общее накопленное время игрока в секундах**, а не время текущей сессии.

Оно используется для начисления наград и статистики профиля: общего времени, активности за месяц, неделю и сегодня, а также календаря активности по дням.

Настрой отправку:

1. Передавай отчёт каждые 5–10 минут, пока игрок онлайн.
2. Отправляй дополнительный отчёт при выходе.
3. Увеличивай `totalSeconds` по мере игры. Значение не должно уменьшаться.

Сайт определяет прирост между двумя отчётами и распределяет время по соответствующим дням. Если промежуток пересекает полночь, время делится между днями. При этом учитывается не более реального времени, прошедшего между отчётами, и не более 12 часов.

Общее время в профиле соответствует присланному `totalSeconds`.

При первом отчёте сайт только сохраняет начальное значение. Восстановить историю до установки плагина невозможно, поэтому календарь активности начинает заполняться со второго отчёта.

Если плагин повторно отправит старое значение `totalSeconds`, сайт проигнорирует его уменьшение.

**Если ты намеренно обнулил счётчики игрока, например после вайпа**, удали его записи из таблиц `player_stats` и `player_day`, чтобы сайт начал собирать статистику заново.

### `clan_membership`: клан игрока

Пример события:

```json
{
  "type": "clan_membership",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "clan": {
    "id": "sunny",
    "name": "Солнечный",
    "role": "owner",
    "members": 14
  }
}
```

Передавай объект `clan`, когда игрок состоит в клане. Используй `null`, если он вышел, его исключили или клан был распущен:

```json
{
  "type": "clan_membership",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "clan": null
}
```

Поле `role` отображается согласно настройкам сайта. Значения `owner` и `member` показываются как «Владелец» и «Житель». Остальные подписи смотри в `clan_ROLE_LABELS` файла `lib/profile/config.ts`.

Отправляй событие:

- при вступлении игрока в клан или выходе из него;
- при смене роли;
- при изменении числа жителей;
- дополнительно при каждом входе игрока на сервер.

Отправка при входе помогает восстановить профиль, если плагин пропустил предыдущее событие.

Не путай `clan_membership` с `clan`. Событие `clan` используется для награды, связанной с числом жителей. `clan_membership` обновляет только данные профиля.

### `donate`: донат-статус

Пример события:

```json
{
  "type": "donate",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "tier": "plus",
  "expiresAt": "2026-12-01T00:00:00Z"
}
```

Поле `tier` содержит код подписки из `DONATE_TIERS` в `lib/profile/config.ts`. По умолчанию доступен код `plus`.

Если отправить неизвестный код, сайт вернёт `invalid` и список допустимых значений. Новые типы подписок сначала добавляй в конфигурацию сайта.

`expiresAt` указывает дату окончания подписки в формате ISO 8601 с часовым поясом, например `Z` или `+03:00`. Если это поле отсутствует, подписка считается бессрочной.

После окончания срока действия сайт автоматически показывает статус «Не куплен».

Чтобы снять подписку, отправь событие с `tier: null`:

```json
{
  "type": "donate",
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "tier": null
}
```

Передавай актуальный донат-статус при покупке, продлении и окончании подписки, а также при входе игрока на сервер.

## 6. Настрой отправку событий в плагине

Для базовой интеграции реализуй следующие действия:

- **Наигранное время:** используй `player.getStatistic(Statistic.PLAY_ONE_MINUTE) / 20`. Несмотря на название статистики, Bukkit возвращает тики. Отправляй `playtime` каждые 5–10 минут и при выходе.
- **Достижения:** обрабатывай `PlayerAdvancementDoneEvent`, а сложность бери из конфигурации плагина. Не отправляй ключи рецептов `minecraft:recipes/...`.
- **Профиль:** отправляй события `presence`, `clan_membership` и `donate` при изменениях. Повторно передавай актуальные данные при входе игрока, чтобы восстановить пропущенные обновления.

### Ответ на запрос событий

Пример ответа:

```json
{
  "results": [
    {
      "status": "credited",
      "amount": 15,
      "balance": 215
    }
  ]
}
```

Результаты идут в том же порядке, что и события в запросе. Ошибка одного элемента не мешает обработке остальных.

Обрабатывай каждый статус отдельно:

| `status`    | Значение                                                                          | Что делать                                                         |
| ----------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `credited`  | Награда зачислена на баланс                                                       | Удали событие из очереди                                           |
| `recorded`  | Данные профиля сохранены                                                          | Удали событие из очереди                                           |
| `pending`   | Игрок ещё не привязал аккаунт. Награда сохранена и будет зачислена после привязки | Удали событие из очереди                                           |
| `duplicate` | Событие уже обработано                                                            | Удали событие из очереди                                           |
| `ignored`   | Событие корректное, но награду не даёт. Например, в клане меньше 10 участников      | Удали событие из очереди                                           |
| `invalid`   | Событие не прошло проверку. Причина указана в `reason`                            | Исправь данные или плагин, затем реши, нужно ли повторить отправку |

### Не теряй события при сетевых ошибках

Храни неотправленные события в очереди, желательно с сохранением на диск. Если возникла сетевая ошибка или сайт вернул `5xx`, повтори запрос.

Начисления идемпотентны: повторная отправка того же события не начислит награду второй раз.

После успешного ответа `200` и разбора результатов удаляй из очереди события, которые получили конечный статус. Для `invalid` сначала выясни причину ошибки.

## 7. Получай заказы магазина

**Метод:** `GET /api/plugin/orders?limit=20`

Плагин регулярно запрашивает заказы, которые нужно выдать игрокам.

Пример ответа:

```json
{
  "orders": [
    {
      "id": 17,
      "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
      "player": "Steve",
      "item": "Алмазы ×16",
      "commands": ["give {player} minecraft:diamond 16"]
    }
  ]
}
```

После получения заказа выполни следующие действия:

1. Определи актуальный ник игрока по UUID. В Bukkit для этого можно использовать `Bukkit.getOfflinePlayer(uuid).getName()`.
2. Если актуальное имя недоступно, используй поле `player`. Оно содержит ник на момент покупки.
3. Для каждой команды замени `{player}` на ник, а `{uuid}` на UUID с дефисами.
4. Выполни команды от имени консоли Minecraft.
5. Подтверди результат только после того, как выдача действительно завершилась.

Запрашивай заказы каждые 10–30 секунд.

Если игрок сейчас не на сервере, а команда требует его присутствия, например `give`, отложи заказ до следующего удобного момента. Не подтверждай заказ, пока товар не выдан.

## 8. Подтверждай результат выдачи

**Метод:** `POST /api/plugin/orders/{id}`

После успешной выдачи отправь:

```json
{
  "status": "delivered"
}
```

Если выдать товар не удалось, отправь:

```json
{
  "status": "failed",
  "reason": "Команда give завершилась ошибкой"
}
```

Результаты отличаются следующим образом:

| Статус      | Результат                                                                          |
| ----------- | ---------------------------------------------------------------------------------- |
| `delivered` | Заказ закрывается как успешно выданный                                             |
| `failed`    | Заказ закрывается, Вторнички возвращаются игроку, остаток товара восстанавливается |

Повторная отправка того же результата безопасна. Сайт может вернуть:

```json
{
  "result": "already"
}
```

Если заказ уже закрыт с противоположным результатом, сайт вернёт HTTP `409 Conflict`. Не пытайся автоматически менять итог закрытого заказа.

## 9. Защити выдачу от повторного выполнения

Сайт может повторно выдать заказ плагину, если тот не подтвердил его в течение 5 минут. Это нужно на случай, если сервер Minecraft упал во время обработки.

Поэтому плагин **обязан сохранять ID уже выданных заказов на диск**.

Когда приходит заказ, который уже был выдан:

1. Не выполняй его команды повторно.
2. Отправь сайту подтверждение `delivered`.
3. Продолжай обработку остальных заказов.

Сохраняй ID надёжно, чтобы после перезапуска Minecraft плагин помнил завершённые выдачи. Иначе повторная доставка заказа сайтом может привести к повторному выполнению команд.
