# Непрерывный график онлайна на Vercel

## Почему появлялись разрывы

Сайт развёрнут на Vercel. Таймер `setInterval` из `instrumentation.ts` не является надёжным планировщиком для serverless-функций: экземпляр функции не обязан постоянно работать между запросами. Раньше дополнительно записывалась точка при открытии страницы статистики, поэтому при низком трафике между точками возникали большие интервалы.

Теперь на Vercel страницу графика не используют как источник замеров. Для регулярного сбора нужно вызвать защищённый endpoint по расписанию.

## 1. Добавь секрет в Vercel

В настройках проекта Vercel → **Settings → Environment Variables** создай переменную:

- Name: `ONLINE_CRON_SECRET`
- Value: случайная строка длиной минимум 32 символа, лучше 64 hex-символа
- Environment: **Production**

Сгенерируй значение менеджером паролей или локально. Не сохраняй секрет в репозитории и не помещай его в URL. После добавления переменной сделай redeploy Production, чтобы новая функция получила переменную.

## 2. Создай расписание

На Hobby-плане Vercel Cron Jobs разрешены только раз в сутки, поэтому для замеров каждые 5 минут используй внешний планировщик, например cron-job.org.

Создай GET-запрос со следующими настройками:

- URL: `https://tuesday-prime.ru/api/cron/online`
- Расписание: каждые 5 минут
- HTTP header: `Authorization`
- Значение заголовка: `Bearer <значение ONLINE_CRON_SECRET>`

Подставь фактическое значение секрета вместо текста в угловых скобках. Не добавляй секрет к URL или query-параметрам.

## 3. Проверь работу

Запусти тестовый запрос вручную. При успехе endpoint вернёт JSON с `ok: true`, `bucket`, `online` и `players`.

- `401 unauthorized`: проверь заголовок Authorization.
- `503 cron_not_configured`: в Production нет `ONLINE_CRON_SECRET`, либо он короче 32 символов; после изменения сделай redeploy.
- `502 server_status_unavailable`: источник статуса сервера временно не отвечает.
- `500 sample_write_failed`: проверь логи Vercel и подключение к базе.

В таблице `online_sample` сохраняется один замер на 10-минутный интервал; повторный вызов в том же интервале обновляет существующую точку вместо создания дубликата. Если источник статуса временно недоступен, этот интервал не записывается. При восстановлении планировщика последующие интервалы продолжат записываться автоматически.

Для локального self-hosted запуска таймер из `instrumentation.ts` продолжает работать. На Vercel он отключён, чтобы не создавать ложное ощущение гарантированного непрерывного планирования.
